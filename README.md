# Coda／尾声

**AI 干完活，也得收好尾。**

任务做完了，临时文件还散着，旧草稿没处理，文档里的名称、路径和引用也没同步。

Coda 帮 AI 把收尾做好：整理成果、修正确认的问题、清理已废弃的临时产物。既能收好本轮任务，也能检查整个工作区；历史遗留先列清单，经你确认后再处理。

[快速开始](#快速开始) · [选择范围](#选择范围) · [安装与调用](#安装与调用) · [收尾边界](#收尾边界) · [English](README.en.md)

## 这些时候，用 Coda 收个尾

| 你让 AI 做的事 | 收尾时检查什么 |
| --- | --- |
| 写报告、改文档、整理交付 | 正式版本能否找到，名称与表达是否有明确错误，目录和引用是否对应实际成果 |
| 查资料、处理数据、做图或制作内容 | 来源与成果入口是否一致，哪些中间产物已废弃，原始素材和必要依赖是否保留 |
| 写代码、调试、运行工具 | 说明和文件路径是否同步，临时文件是否仍有用，任务启动的临时进程是否还需要 |

两个独立的纯指令技能，源码使用英文，执行时随用户语言回复。技能本身无需脚本、运行时依赖或网络服务；具体任务使用的工具和权限由客户端提供。仅在明确调用时运行。

## 快速开始

### 复制一句话，让 AI 安装

将下面这段话发给支持技能安装、且有相应操作权限的 AI 客户端：

```text
帮我安装这个仓库里的 coda 和 coda-workspace 两个技能：
https://github.com/H-Bole/coda
```

安装 AI 应先读取本页的[安装与调用](#安装与调用)，识别两个技能源目录、当前宿主及已有安装管理方式，避免重复安装或覆盖现有配置。安装完成后刷新技能或开启新会话，检查两个入口是否可发现。

### 在 Codex 中第一次使用

收好本轮任务：

```text
$coda 请为本轮任务收尾。
```

检查整个工作区：

```text
$coda-workspace 请检查当前工作区，列出需要整理、修正和清理的历史候选。
```

也可在技能选择器中选择对应入口。[Claude Code 的调用与配置](#claude-code)见下文。

## 选择范围

| 技能 | 适合什么时候用 | 历史内容怎么处理 |
| --- | --- | --- |
| [`coda`](skills/coda) | 本轮工作做完：整理成果、修正确认的错误、清理废弃产物与临时进程 | 不扩展到无关历史内容 |
| [`coda-workspace`](skills/coda-workspace) | 工作区需要整体收尾：检查整理、纠错与清理候选 | 历史修正、移动、删除和进程处理先列具体候选，逐项获批，执行前复核；变化则跳过 |

两个技能各自包含完整的 `SKILL.md` 和 `agents/openai.yaml`，可以分别安装。不因任务完成自动触发，也不要求每轮新建总结文件。

### 一个文档任务的收尾示例

你刚让 AI 完成一份报告。任务记录确认正式成果为“调研报告”，交付入口却写成“调研报高”、指向不存在的旧草稿，而正式文件已经存在。

Coda 应依据实际成果修正名称和入口，保留原始资料及仍被引用的附件；仅在确认草稿属于本轮、已废弃且无引用或占用后清理。归属不明的旧文件继续保留。

这是行为示例。含义、事实或选择尚不明确的问题，应报告依据和建议；历史修正使用工作区技能的审批流程。

## 为什么做 Coda

最近高强度 Vibe Coding，我发现 Codex 经常干完活就留下一堆烂摊子。叫它清理，它又说被拦截了，最后还得我自己擦。

后来发现，那次批量清理被阻止，缩小到逐个核对、逐个删除，还是成功了。我把这些经验整理进 Coda，也补上成果整理、表达与引用纠错，以及工作区级别的收尾。

写文档、查资料、做内容，同样会遇到这些问题，所以 Coda 面向所有需要收尾的 AI 任务。

那次成功来自已有授权内缩小操作范围、逐项核验；遇到明确禁止或较小操作仍被阻止时，仍应停止并说明具体限制。

## 安装与调用

### 给安装 AI 的说明

1. 读取仓库说明，分别识别 [skills/coda](skills/coda) 和 [skills/coda-workspace](skills/coda-workspace)。仓库根目录不是单个技能目录。
2. 检查当前宿主支持的技能位置、已有同名技能和管理方式。保留已有配置及共享源，不因目录与其他客户端不同而自行迁移。
3. 依照宿主或现有管理器支持的方式安装两个完整技能目录。发现同名项时核对来源和版本；更新已有安装前确认用户意图，不覆盖无关技能或制造重复入口。
4. 按下方宿主说明配置明确调用方式；刷新技能或开启新会话，检查两个入口各出现一次，并报告安装位置和仍需用户完成的步骤。

本仓库提供技能文件，不附安装脚本。安装不授予额外的系统配置变更权限。

### 使用 Magpie 管理

1. 获取[仓库](https://github.com/H-Bole/coda)，按 Magpie 实际支持的导入方式操作。
2. 分别选择两个技能目录导入：[skills/coda](https://github.com/H-Bole/coda/tree/main/skills/coda) 和 [skills/coda-workspace](https://github.com/H-Bole/coda/tree/main/skills/coda-workspace)。不要假定导入根目录就会自动安装两者。
3. 刷新宿主或开启新会话，确认两个技能入口各出现一次。
4. 通过 Magpie 管理更新与卸载，保留可能被其他安装共用的源目录。不要另外手工建立与现有管理器重复的链接。

实际安装位置由 Magpie 和客户端决定；安装或发现失败时先核查原因。本说明不依赖特定 Magpie 菜单名称。

### Codex

在技能选择器中选择，或明确输入 `$coda` / `$coda-workspace`。支持 `/skills` 的 CLI、IDE 宿主也可通过该入口选择；不保证 `/coda` 是 Codex 的斜杠命令。

两个技能的 `agents/openai.yaml` 均声明 `policy.allow_implicit_invocation: false`，仅在用户明确调用时使用。

### Claude Code

调用 `/coda` 或 `/coda-workspace`。两个技能使用通用标准 frontmatter；宿主层的明确调用配置见下方，Claude Code 尚未实机验证。

## 收尾边界

- **先核实，再动手。** 读取项目规则，检查归属、引用、依赖和占用；名称、时间戳或 Git 状态不能单独证明可删。
- **纠错要有依据。** 根据任务要求、实际成果和可信来源修正范围内的明确错误，保持原意和结构。含义或事实不明时报告问题与建议；引用访问失败本身不能证明引用错误。
- **历史改动先批准。** 工作区技能对历史修正、移动、删除和进程处理先列具体对象、依据和动作。执行前复核，内容、引用、占用或身份变化则跳过，重新取得批准。
- **保留需要留下的东西。** 原件、正式成果、必要依赖、共享资源、仍在使用和归属不明的内容保留。已有合理位置的成果不为整理而迁移；必要移动先检查引用和冲突。
- **进程身份要对得上。** 结合任务关联、启动时间和命令行判断，关闭前重新核验；不单凭 PID、名称或端口操作。非任务、常驻、共享或用途不明的进程保留。
- **Windows 逐项处理。** 优先使用精确绝对路径的 `Remove-Item -LiteralPath`，不默认加 `-Force` 或 `-Recurse`。目录检查内容后逐项处理，确认空后删除；核对链接及父路径边界，只删链接本身，不进入共享目标。
- **阻止后先缩小范围。** 批量命令被阻止且已有清理授权时，可用同一工具每次仅执行一条删除命令、处理一个精确路径，逐项复核，不强制、不递归。历史项仍须具体批准；明确禁止或较小操作仍被阻止时停止并报告，不换工具或提权绕过。仅有 `blocked by policy` 不代表存在自动审批拒绝。
- **守住收尾范围。** 不扩展为全文润色、业务改造或未经请求的全面审计；不默认清共享缓存、安装依赖、扩大测试、提交或推送。

完成后简短报告整理、修正、删除、关闭、保留或跳过了什么，以及未完成或未验证的事项。文件逻辑大小与实际磁盘空间变化分开报告；没有实测就不声称释放了多少空间。

## 验证状态

验证涵盖技能格式与入口配置检查，以及隔离场景中的纠错和清理检查。场景检查不等同于独立模型评测或宿主验收。

实际安装、刷新及入口调用须在目标客户端验收；本文未对 AI 一句话安装或 Magpie 安装进行端到端验收，Claude Code 尚未实机验证。入口可见不等于全部行为边界已验证。
